Transformer based network architectures have shown excellent performance at autoregressive generation tasks i.e., adding onto and completing a given input sentence (prompt) one word at a time. This post uses all the neural network primitives discussed so far to assemble a network and trains it on the [TinyShakespeare](https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt) dataset to generate text akin to writings of Shakepeare. The aim is to develop an intuitive understanding of the process of training a neural network in JAX and (hopefully) culminating in a fun toy model to keep as a personal Bard. :)

### Tokenization
Computers do not understand language and text in the traditional sense; they use numerical representations to work with them (think UTF encoding). Neural networks, essentially a computational graph of mathematical operations, work the same way. Tokenization is the process of breaking up continuous strings of text into smaller chunks, tokens. Depending on the strategy, these smaller chunks can be characters, words or sub-words. You might think words as tokens is a good strategy, after all it naturally breaks up text into smaller meaningful pieces that are composed into sentences and paragraphs. A major drawback of using words is the sheer number of unique tokens that will be in the vocabulary and balloon up the size of the model (recall, the final layer of the network outputs a distribution over the entire vocabulary and each prior layer will have to be scaled accordingly to learn any meaningful relationship). Any word that the model has not seen during its training will be an `<UNKNOWN>` token and thus, would lead to issues when this model is deployed in production.

Character level encoding runs into a similar vocabulary problem if we try to map the ~150k unique Unicode characters across all global languages. Alternatively, if we drop down to the raw computer bytes that make up these characters (values from 0-255), we get a tiny, manageable alphabet. However, pure byte-level encoding forces the model to learn the complex task of spelling words in addition to learning the semantic relationship between those words. Additionally, it exhausts the context window of a model—the number of tokens it can process at a time. Since each character in a sentence is an independent token, the model either cannot process long chunks of text at a time, or it becomes really big in size and necessitates a large amount of memory to run.

#### GPT-2 Tokenizer

The GPT2 tokenizer (code from OpenAI available here) offers a reasonable middle ground to character and word level encoding using Byte-Pair Encoding (BPE). It is the tokenizer used in the GPT2 model (groundbreaking performance on next word prediction at the time of release). Consider the sentence, `I'm learning AI!` as an example. During inference, it follows the below steps to convert text into numerical IDs:

1. **Regex Pre-splitting:** The tokenizer uses regex to split words in the text in order to make them more conducive to learning patterns in the English language. For instance, `'s`, `'ll`, `'ve` etc. are split from their base words so they are tokenized separately. This allows the model to treat these as additions to base words instead of "He'll" being treated as a unique word. Following similar reasoning, punctuations are separated from their preceding words and the preceding space character is folded into the following word. Hence, the example sentence is broken up as: `["I", "'m", " learning", " AI", "!"]`.
2. **Byte level mapping:** Every character of each element in the array obtained from the previous step is converted into its raw UTF-8 bytes. Thus, every piece of text is fundamentally represented by a sequence of numbers from 0-255. Representing text using raw bytes enables the tokenizer to handle characters from unseen languages—which just become sequences of multiple bytes—thus solving the problem posed by `UNKNOWN` tokens. However, raw bytes for invisible control characters, like `null`, `\n` etc., are difficult to safely serialize into standard JSON dictionary files or visually inspect during debugging. So, any byte that is not strictly a visible ASCII character is mathematically shifted into a visible Unicode character block. Thus, our array from the previous step after this shifting becomes: `["I", "'m", "Ġlearning", "ĠAI", "!"]`. Notice the space character is shifted and represented by the visible character `Ġ`. See the `bytes_to_unicode` method in the GPT2 implementation for more details on which characters are mapped.
3. **Applying Byte-Pair Encoding:** The next step is merging the bytes into recognized subwords using pre-learned rules. *Before* processing our sentence, the tokenizer was trained on a massive input corpus. During that one-time training after performing steps 1 and 2 on the input corpus, it found the most frequent pair of adjacent bytes, minted a new token ID (ID > 255) for that pair, and iteratively repeated the search -> mint -> merge process 50,000 times. This built a static vocabulary of 50,257 tokens (256 base bytes + 50,000 minted merges + 1 `<endoftext>` token), saved as a `vocab.json` and a `merges.txt` file. The tokenizer after each iteration represents the most common words using unique token IDs and the others as a combination of these tokens thus enabling an efficient use of the model's available context window when processing the input corpus. Now, when processing our live sentence, the tokenizer simply applies those saved merge rules to our shifted chunks. Because `Ġlearning` is a common word, the rules iteratively merge the individual letters all the way back into the single subword `Ġlearning`.
4. **Vocabulary Lookup:** Finally, the tokenizer looks up each resulting BPE subword in its 50,257-token vocabulary dictionary and replaces it with its corresponding numerical ID. Our array is converted into the final integer sequence: `[40, 1101, 4673, 9552, 0]`. The neural network can now mathematically process the text.

## Network Architecture

A standard architecture of a decoder only Tranformer based network for an autoregressive task follows the flowchart below. Input token IDs are converted to token embeddings and position embeddings. Each token ID in the vocabulary is represented as a high dimensional vector. The numerical values in this vector is learned as part of the gradient descent training. Attention processes all tokens in the input at once, therefore, to allow it learn the sequential nature of language an additional Position embedding is added to each token embedding vector. Position embeddings, as well, are high dimensional vectors unique for each position in the input sequence. The dimensionality of these vectors is a hyperparameter of the model architecture, called Embedding dimension. Larger embedding vectors allow the model to learn more complex semantic relationships in input at the cost of increasing the model size and requiring more data to learn these relationships effectively.

Token embeddings can thus be represented as a matrix with dimensions `vocab_size * embed_dim`, each row consisting of the embedding dimension for a token ID. Similarly, position embedding matrix will have the dimensions `context_len * embed_dim`, each row here indexed on the position in the input sequence where `context_len` is the number of tokens the model can process at a time. 

The sum of these embeddings is input to the layers of Transformers and then passed through a LayerNorm and then transformed using a linear layer to the shape `context_len * vocab_size` i.e. for each token in the input the output is a `vocab_size` vector consisting of scores for each word in the vocabulary quantifying its probability to be the next word after a token. During inference (when the model is generating text), only the final row of this output is relevant for predicting the single next word. During training, however, the model utilizes the entire output matrix at once, comparing every predicted token against the actual next word in the sequence to calculate its error.

Note, `B` is the batch size. Batches allow loading up multiple context length size inputs in memory before passing them through the network. Since each input sequence in a batch is independent of the next, they can be processed in parallel thus maximising utilization of the available hardware. While this parallelism improves computational efficiency, the choice of batch size during training is also a critical hyperparameter that directly impacts how the model calculates its gradients and updates its learned weights.

## Training the network

In addition to Flax, this post utilizes some other libraries during the training process to maintain focus of network architecture and training a machine learning model instead of JAX nuances.

### Optimizer from Optax 

The simple strategy of learning rate based weight updates is not optimal for deep neural networks. As networks grow in size learning rate scaled weight updates become erratic and delay the convergence of the network. Adam is an optimization strategy that solves this problem by using a variable learning rate. The weight updates for each weight are adapted at every training step according to exponential moving averages of the gradient values and gradient values squared. The updates are also dependent on hyperparameters called decay which decays the scale of weight updates as the training process progresses. Adam has been shown to provide faster network convergence over simple Stochastic gradient descent [^adam]. Adam is susceptible to overfitting wherein, the model performs really well on its training data but struggles to achieve same level of performance on unseen inputs. AdamW [^adamw] applies an independent weight decay and achieves better performance. Here are good resources to for further reading on mathematics of [Adam](https://optimization.cbe.cornell.edu/index.php?title=Adam) and [AdamW](https://optimization.cbe.cornell.edu/index.php?title=AdamW) optimizers.

Optax is a JAX library which provides implementations for these optimization strategies. It handles keeping track of momentums (exponential moving averages) for each weights and its scaled updates.

### Checkpointing using Orbax

When training neural networks saving states of the network, a snapshot of all model weights at a given instantjis prudent. This safeguards against an error during the training process so any progress is not lost and also enables comparing the model's outputs at various stages of the training. The latter is especially useful for comparing performance during hyperparameter tuning or other forms of experimentation. Orbax is a library which makes checkpointing and storing network states easy in JAX.

### The code

```python
class Model(nnx.Module):
  def __init__(self, embed_dim, seq_len, vocab_size, n_heads, mlp_hidden_dim, n_layers, rngs: nnx.Rngs):
    self.embed_dim = embed_dim
    self.n_heads = n_heads
    self.mlp_hidden_dim = mlp_hidden_dim
    self.n_layers = n_layers

    self.seq_len = seq_len
    self.vocab_size = vocab_size

    self.token_embedding = nnx.Embed(vocab_size, embed_dim, rngs=rngs)
    self.position_embedding = nnx.Embed(seq_len, embed_dim, rngs=rngs)

    self.layers = [Transformer(embed_dim, n_heads, mlp_hidden_dim, rngs=rngs) for _ in range(n_layers)]

    self.ln = nnx.LayerNorm(embed_dim, rngs=rngs)
    self.head = nnx.Linear(embed_dim, vocab_size, use_bias=False, rngs=rngs)

  def __call__(self, input_ids, attention_mask):
    # input_ids: (Batches, seq_len)
    # attention_mask: (Batches, seq_len)
    attention_mask = jnp.expand_dims(attention_mask, axis=-1)

    t_embeds = self.token_embedding(input_ids.astype(jnp.int32)) # (Batch, SeqLen, EmbedDim)

    p_embeds = self.position_embedding(jnp.arange(input_ids.shape[1])) # (SeqLen, EmbedDim)

    x = t_embeds + p_embeds

    for layer in self.layers:
      x = layer(x, attention_mask) # Pass embedded sequence 'x' and mask to transformer layer

    norm_x = self.ln(x)

    logits = self.head(norm_x)

    return logits
```
